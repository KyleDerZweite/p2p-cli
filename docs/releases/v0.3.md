v0.3 adds working Linux text chat over one authenticated connection. Both peers send and receive through that connection, so only the listener needs a reachable TCP port. The program reports version `0.3.0`.

- Share an invitation with your public identity and candidate addresses. The connecting peer checks the identity before sending application data and tries another address if the first fails.
- Both peers authenticate the Noise handshake with Ed25519. Messages also undergo signature, replay, and conversation-state checks.
- Keep encrypted history across restarts, or use `--security max` for memory-only history and trust. Maximum mode still keeps your identity file.
- Paste invitations and messages into the terminal. Pasting does not send the text; press Enter when ready.
- Use `--diagnose` to inspect addresses and TCP reachability. Use `--log FILE` for private network diagnostics that exclude chat text and keys.

Download `p2p-cli-linux-x86_64` and `SHA256SUMS` into the same directory, then run:

```sh
sha256sum --check SHA256SUMS
chmod +x p2p-cli-linux-x86_64
./p2p-cli-linux-x86_64 --help
```

The binary is built on Ubuntu 22.04 for x86-64 Linux with glibc. Build from source on other architectures or distributions that cannot run it. Install iproute2 for local IPv4 and IPv6 address discovery.

Generate an invitation with `--invite`, share it with the other person through a channel where they can verify who sent it, then start the listener without that flag. The other person runs `--connect '<invitation>'`. The listener approves the incoming conversation. See the [README](https://github.com/KyleDerZweite/p2p-cli/blob/v0.3/README.md) for the full workflow.

Both peers must upgrade. This transport does not connect to v0.2.0. Existing identity and storage keys remain usable. Older history indexed by temporary session identifiers remains on disk but is not automatically assigned to a permanent identity.

Chat requires no relay, account, public IP lookup, or third-party discovery service. A LAN route, reachable IPv6 address, or manually forwarded IPv4 port is still necessary. Some networks cannot connect directly. A timeout does not prove which router or firewall blocked the connection.

Messages have no delivery receipts or automatic retransmission. A failed send can have uncertain delivery. This release covers pairwise text chat; file transfer, groups, automatic router mapping, and LAN broadcasts remain deferred. The cryptographic implementation has not received an independent audit.

Validation includes 43 Rust tests and real Linux terminal tests for two-way chat, restart, history recovery, invitation fallback, identity rejection, paste, private logs, and Maximum mode.
